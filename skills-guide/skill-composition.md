# Skill composition

Codex skills can form a pipeline or supply complementary guidance, but custom
frontmatter keys do not load another skill. Keep `SKILL.md` frontmatter limited
to `name` and `description`.

## Pipeline relationship

One skill consumes another skill's artifact. Document expected input in body and
link directly to producer:

```markdown
Convert a PRD generated by [`codex-prd`](../skills/codex-prd/SKILL.md) into Chronis tasks.
If no PRD exists, ask user to invoke `$codex-prd` first.
```

`codex-prd` → `codex-beads` is current example.

## Complementary relationship

One task benefits from two independent skill bodies. Tell Codex which skill to
load and why:

```markdown
For TypeScript findings, also use `$typescript` for language-level rules.
```

Useful pairs:

| Primary | Complement |
|---|---|
| `perf-review` | `typescript` or `security-review` |
| `security-review` | `typescript` |
| `explain-module` | `arch` |
| `integration-test` | `bun-testing` for Bun projects |
| `rust-clean-architecture` | `rust-quality` |

## Default prompts

`agents/openai.yaml` may suggest a composed invocation:

```yaml
interface:
  default_prompt: "Use $perf-review and $typescript to review this TypeScript hot path."
```

This helps explicit invocation; it is not a dependency engine.

## Rules

- Link only real relationships.
- Do not duplicate another skill's full instructions.
- Load only references needed for current request.
- Make missing pipeline inputs explicit.
- Never rely on unsupported `depends_on` or `enhances` frontmatter.
