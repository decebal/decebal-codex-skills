# TS Protobuf codegen: comparison

Four ways to turn `.proto` into TypeScript. The browser-critical column is
**CSP-safe** — whether the generated code or its runtime uses `eval` / `new
Function()`, which a strict `script-src` (no `unsafe-eval`) blocks, killing the
code on load on any hardened host page.

| Tool | Runtime dep | ESM | CSP-safe (no eval/`new Function`) | gRPC-Web | Notes |
|---|---|---|---|---|---|
| **protobuf-es** (`@bufbuild/protobuf`) | small, tree-shakeable | yes (ESM + CJS) | **yes** | via Connect-ES (`@connectrpc/connect-web`) | Generated by `protoc-gen-es`; schema-function API (`toBinary(Schema, msg)`); driven by `buf`. **Recommended for browser/CSP.** |
| **google-protobuf** | `google-protobuf` (large) | no (CommonJS) | **no** — uses `new Function()` in reflection/serialization | via `protoc-gen-grpc-web` | The reference JS impl; not tree-shakeable, breaks under strict CSP. Legacy. |
| **ts-proto** (`protoc-gen-ts_proto`) | none/minimal (self-contained output) | yes | **yes** (plain generated TS) | via generated grpc-web / nice-grpc | A `protoc` plugin, highly configurable output. CSP-safe, but you drive `protoc` (or buf with a local plugin) rather than the buf-native path. |
| **protoc-gen-grpc-web** | `google-protobuf` for messages | no | **no** (inherits google-protobuf) | yes (its whole purpose) | Official gRPC-Web codegen, but its messages ride on google-protobuf — same CSP problem. |

## Recommendation

- **Browser under strict CSP → protobuf-es** (+ Connect-ES for gRPC-Web). It is
  the only mainstream option that is simultaneously ESM, tree-shakeable, CSP-safe,
  and first-class in the `buf` workflow.
- **google-protobuf / protoc-gen-grpc-web** only where a strict CSP is not in play
  and legacy code already depends on them — and even then, migrating off is the
  standing direction (see M1 in [../../security-review/SKILL.md](../../security-review/SKILL.md)).
- **ts-proto** is a solid CSP-safe alternative when you want zero-runtime output
  or its specific codegen knobs; it just sits outside the buf-plugin ecosystem.

Whichever you pick, prefer one runtime across the app — a second protobuf runtime
is dead weight ([../../../rules/dependency-hygiene.md](../../../rules/dependency-hygiene.md)).
